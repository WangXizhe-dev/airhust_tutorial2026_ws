# 板块四 · 我怎么验证这五次飞行

我把每一关拆成三个能单独核对的问题：飞机到指定位置了吗？相机在那里读到了什么？最后落在靶上了吗？例如第一关，飞到地图里的 (1, -1) 只能说明飞机到了红块附近。终端里的 red 来自那一刻的相机画面。把画面一起存下来，答辩时就能对着图解释。

## 在课程虚拟机里复现

在装有 ROS Noetic、PX4 SITL、Gazebo 和课程 simulation 包的 Ubuntu 终端执行。下面按本机的克隆位置写。五关轮流使用同一组仿真端口，启动前先关闭已有的课程 roslaunch。

```zsh
cd ~/airhust_tutorial2026_ws/3关/airhust_tutorial26_vision_lab
source ~/airhust_ws/devel/setup.zsh
catkin_make -j2
source devel/setup.zsh
export ROS_PACKAGE_PATH=$ROS_PACKAGE_PATH:$HOME/PX4-Autopilot:$HOME/PX4-Autopilot/Tools/sitl_gazebo
source ~/vision-deps/venv/bin/activate
cd src/lab_vision_sim_task4
bash scripts/suite.sh ~/airhust-runs/$(date +%Y%m%d-%H%M%S) 1 2 3 4 5
```

最后一行只留一个编号就可以重跑对应关卡。输出目录里按编号保存 launch.log、mission.log、相机截图和 result.json。用不同的输出目录可以保留每一次尝试。本机虚拟环境可以访问系统的 ROS Python 包，并从虚拟环境加载 OpenCV、NumPy、PyTorch 和 Tesseract 包装命令。

## 飞行和视觉各负责什么

- **航点和降落。** ROS 定时器持续把位置设定值发送给 MAVROS。PX4 收到稳定的数据流后，节点才请求 OFFBOARD 并解锁。课程地图使用 Gazebo 世界坐标，脚本根据模型位姿和 MAVROS 本地位姿的差值换算目标。这个做法依赖仿真真值。视觉用于到点后的识别，航线使用题目给定的坐标。
- **颜色。** 到 1.5 米悬停后依次去三个圆上方。取画面中央的一小块，按 HSV 色相统计红、绿、蓝的像素比例。饱和度门槛能排掉灰地面，红色需要同时考虑色相范围两端。
- **二维码和 AprilTag。** 二维码解出一串文字，先试多码接口，再试单码接口。AprilTag 用 36h11 字典解出编号。两关都读取 /usb_cam/image_raw 的新帧，经 cv_bridge 转为 BGR。
- **文字。** 找到较亮的牌面，裁剪、放大，然后让 Tesseract 按单行大写文本读取。画面旋转会改变阅读方向，所以可以尝试四种朝向。只有实际读到 AIRHUST 才进入降落步骤。
- **Logo。** 我用课程的 logo.png 生成了 80 张训练图和 24 张验证图。每张正样本先做几何变换，再把四角投影得到的外接框写成归一化 YOLO 标注。没有贴 Logo 的灰背景样本保留空标签。训练从上个板块的 nano 权重开始，换成 AirHust 单类别，CPU 上跑 14 轮。验证集也来自合成图，真正的实用检查是把模型接到 Gazebo 相机上。复训命令如下。

```zsh
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=1 YOLO_OFFLINE=true python scripts/train_logo.py ~/vision-deps/logo-training
```

## 怎么判断降落成功

每关识别达到要求后，脚本向 PX4 请求 AUTO.LAND。等到飞控自动上锁才读取模型的实际位置。result.json 中的 error_m 是落点和靶心之间的水平直线距离，单位是米。本次统一采用距离小于 0.30 米、模型高度小于 0.30 米的判据。第一关用蓝色圆心 (1, 1)，其余四关用 (1, 0)。这样能直接区分“飞过靶标”“读到了内容”和“落在靶上”。
