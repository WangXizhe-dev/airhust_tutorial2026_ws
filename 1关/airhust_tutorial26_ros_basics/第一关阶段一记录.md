# 第一关阶段一的日志

思考路径：第一次跑 `catkin_make`，报错里说：CMake 已经找到了 `geometry_msgs`，catkin 却说 `package.xml` 没有把它声明为构建依赖。顺着报错对照两个文件，发现 `geometry_msgs` 和 `std_msgs` 都写在了 `CMakeLists.txt` 里，包清单却漏掉了它们。

修改内容：

1.在 `package.xml` 里补齐依赖

因为项目中的 flight_node.cpp 使用了这些包提供的消息类型：geometry_msgs/PoseStamped.h和std_msgs/Float32.h

所以要在package.xml 中声明

原本只写了drone_backend的构建依赖和运行依赖

我把构建依赖与运行依赖合写成了一个<depend>，

以补上构建导出依赖（因为下面的 `CATKIN_DEPENDS` 会导出它）

``<depend>drone_backend</depend>
<depend>geometry_msgs</depend>
<depend>std_msgs</depend>``

并且补齐了geometry_msgs和std_msgs的依赖。


2.在 `CMakeLists.txt` 里补齐后端依赖

因为项目中的 example_listener.cpp 使用了：

#include <drone_backend/DroneState.h>

所以查找依赖包时要加上drone_backend

``find_package(catkin REQUIRED COMPONENTS
  roscpp
  drone_backend
  geometry_msgs
  std_msgs
)``

对应的，声明 Catkin 导出依赖时也要加上drone_backend

``catkin_package(
  CATKIN_DEPENDS roscpp drone_backend geometry_msgs std_msgs
)``

其中，find_package的作用是查找当前构建需要使用的软件包

而catkin_package的作用是生成当前 Catkin 包的构建配置，声明导出依赖


3.给 `flight_node.cpp` 配一个构建目标

因为因为 mission.launch 中写了：

``<node pkg="drone_bringup"
      type="flight_node"
      name="flight_node"
      output="screen"/>``
      
其中 type="flight_node" 要求 ROS 找到能够运行的 flight_node 程序。

而CMakeLists.txt只定义了一个名为 example_listener 的构建目标

因此还要为flight_node配一个构建目标。

所以我加了这两行

``add_executable(flight_node src/flight_node.cpp)
target_link_libraries(flight_node ${catkin_LIBRARIES})``

先定义构建目标（生成可执行文件）（附上源文件）

再把 flight_node 与 Catkin 提供的相关库链接起来。
