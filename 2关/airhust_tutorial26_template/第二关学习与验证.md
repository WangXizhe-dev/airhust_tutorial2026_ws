# 第二关 · 用里程计判断一圈有没有走完

这次选了离散航点。最容易看错的一步是回到起点：飞机还没动时，也可能离起点很近。所以程序先到圆周起点，再按顺序走完 12 段，最后一次到达起点才算闭合。

## 练习一：原模板怎样从 case 2 切到 case 3

原来的 case 2 调用 `mission_pos_cruise(4.0, 0.0, ALTITUDE, 1.57, err_max)`。目标 XYZ 会加上起飞参考位置；目标 yaw 是 1.57 rad。实际位置的三个轴分别满足绝对误差小于 `err_max`，而且 yaw 的绝对误差小于 0.1 rad，函数才返回 true。原函数直接比较 yaw 差值，跨越正负 π 时要留意角度跳变。

`local_pos_cb` 订阅 MAVROS 的里程计，收到消息后把它保存到 `local_pos`，同时用姿态四元数更新 yaw。函数返回 false 时，程序跳出 switch，仍会发布本轮设定点、调用 `ros::spinOnce()` 处理新反馈，再按 20 Hz 等待下一轮。因为 `mission_num` 没变，下一轮还是 case 2。返回 true 才更新阶段号，下一轮进入 case 3。

## 练习二：用速度接近一个点

这个短练习假设飞机已在目标高度，目标 yaw 为零。每次循环用最新里程计重新计算误差。下面的 C++ 片段放在对应任务阶段内，`ex/ey/ez` 是同一坐标系下目标减实际的位置误差，`yaw_error` 是归一化到正负 π 的角度误差。

```cpp
setpoint_raw.coordinate_frame = 1;
setpoint_raw.type_mask = 1 + 2 + 4 + 64 + 128 + 256 + 2048;
setpoint_raw.yaw = 0.0;
const double vx = 0.5 * ex, vy = 0.5 * ey;
const double speed = std::hypot(vx, vy);
const double scale = speed > 0.6 ? 0.6 / speed : 1.0;
const bool arrived = std::abs(ex) < err_max && std::abs(ey) < err_max &&
                     std::abs(ez) < err_max && std::abs(yaw_error) < 0.1;
setpoint_raw.velocity.x = arrived ? 0.0 : scale * vx;
setpoint_raw.velocity.y = arrived ? 0.0 : scale * vy;
setpoint_raw.velocity.z = 0.0;
```

主循环随后发布这条消息，完成本轮后再切换阶段。这里把水平合速度限制在 0.6 m/s，等比例缩放能保住原来的方向。分别限制两个轴时，对角线上的合速度可能超过上限。如果只算一次，飞机越过目标后仍会收到原来的速度，无法随误差减小而减速，也不会在越过后纠偏。这个片段是速度题的推演，正式绕圈使用下面的位置控制。

## 正式任务怎么走

- **等待数据。** 收到飞控连接状态和有时间戳、位置与 yaw 有限的里程计后，保存第一帧有效位置为原点。原模板用高度非零判断初始化；地面高度也可能恰好为零，因此改用消息本身判断是否就绪。
- **起飞和入圈。** 沿用模板的发布器、模式服务、解锁服务和位置函数。相对高度目标为 0.80 m，确认 OFFBOARD、已解锁且实际到达起飞目标后，再飞往圆周起点。
- **绕圈。** 圆心在起飞原点的水平投影。第 k 个目标为 `(r cos(2πk/N), r sin(2πk/N), 0.8)`，yaw 固定为零。先到 k=0，再从 1 走到 N；只有位置函数读到实际到达反馈，编号才加一。配置会检查相邻航点的容差区域是否重叠，避免点数太密时一次位置反馈就能满足相邻目标。
- **悬停和降落。** 到达 k=N 后继续发布圆周起点，按 ROS 仿真时间悬停 3 秒，然后请求 AUTO.LAND。程序以飞控已上锁、相对原点高度绝对值小于 0.25 m 作为结束条件。原模板按下降计时结束；这里等飞控反馈，更方便核查。两轮测试的着陆高度对起飞参考仍有约 0.2 m 偏差，日志保留了原始值。

## 在课程虚拟机里复现

终端一加载镜像的环境后启动仿真。本次使用无 GUI 模式，让有限的虚拟机内存留给物理仿真和飞控。

```zsh
source ~/airhust_ws/devel/setup.zsh
export ROS_PACKAGE_PATH="$ROS_PACKAGE_PATH:$HOME/PX4-Autopilot:$HOME/PX4-Autopilot/Tools/sitl_gazebo"
roslaunch simulation sim.launch gui:=false interactive:=false enable_cloud_register_mapping:=false
```

终端二进入第二关的独立工作空间。节点提示时输入 `1` 开始。

```zsh
cd ~/airhust_tutorial2026_ws/2关/airhust_tutorial26_template
catkin_make -j2
source devel/setup.zsh
rosparam load src/template/config/template.yaml
rosrun template template
```

默认参数为 `circle_radius: 1.0`（米）、`circle_points: 12`（段）、`err_max: 0.15`（各轴位置容差，米）、`if_debug: 1`（仿真自动请求 OFFBOARD）。验证改参时，在第一次着陆、节点退出后执行 `rosparam set /circle_radius 1.4`，再次运行节点。重新加载 YAML 可恢复默认值。

## 两次实跑和演示

| 半径 | 到达圆周起点 → 返回起点（仿真秒） | 绕行用时 | 悬停用时 | 结束反馈 |
| --- | --- | --- | --- | --- |
| 1.0 m | 96.805 → 115.756 | 18.951 s | 3.049 s | 已上锁，相对高度 −0.217 m |
| 1.4 m | 220.683 → 242.583 | 21.900 s | 3.000 s | 已上锁，相对高度 −0.242 m |

预测是半径变大后，相邻航点更远，绕行耗时会增加。两轮保持 12 段，实测增加约 2.95 个仿真秒。途中坐标会有跟踪误差，例如第二轮回到起点时实际相对位置为 (1.335, −0.138, 0.813) m，对应目标为 (1.4, 0, 0.8) m，三轴误差都在 0.15 m 内。
