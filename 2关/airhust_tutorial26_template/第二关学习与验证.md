## 练习一：
① 哪些位置和朝向条件满足时，函数返回 true？

XYZ 三轴实际位置与目标位置的绝对误差分别小于 err_max，且实际 yaw 与目标 yaw 的绝对误差小于0.1弧度，这四个条件同时满足时。

② local_pos.pose.pose.position.x/y/z 在什么时候更新，由谁更新？

当消息到达且 spinOnce() 处理回调时，local_pos_cb() 通过 local_pos = *msg 更新实际位置信息。

③ 如果这次返回 false，这一轮后面还会执行什么，下一轮执行哪个 case？

mission_num 保持为2，break 跳出 switch，随后继续执行 publish、spinOnce 和 rate.sleep。下一轮仍进入 case 2。
## 练习二：用速度接近一个点
我的代码实现：
（注：`ex/ey/ez` 是同一坐标系下目标减实际的位置误差）
```cpp
setpoint_raw.coordinate_frame = 1;
setpoint_raw.type_mask = 1 + 2 + 4 + 64 + 128 + 256 + 2048;
setpoint_raw.yaw = 0.0;
const double vx = 0.5 * ex, vy = 0.5 * ey;
const double speed = std::hypot(vx, vy);
const double scale = speed > 0.6 ? 0.6 / speed : 1.0;
const bool arrived = std::abs(ex) < err_max && std::abs(ey) < err_max &&
                     std::abs(ez) < err_max && std::abs(yaw_error) < 0.1;
setpoint_raw.velocity.x = arrived ? 0.0 : scale * vx;
setpoint_raw.velocity.y = arrived ? 0.0 : scale * vy;
setpoint_raw.velocity.z = 0.0;
```
应该把速度计算放在主循环中对应的任务阶段，例如 case2中。
这样每轮循环都能根据最新的位置反馈重新计算误差和速度，填写 setpoint_raw，再由主循环统一发布消息。
限制合速度的好处：1.等比例缩放能保住原来的方向。2.分别限制两个轴时，对角线上的合速度可能超过上限。
如果只算一次，飞机越过目标后仍会收到原来的速度，无法随误差减小而减速，也不会在越过后纠偏。

怎样判断绕圈完成：
由于刚开始时飞机也可能位于起点附近，所以用waypoint计数，waypoint==12且回到起始点时绕圈完成。
为什么航点数量越多不一定越好：
点数越多，理论轨迹越接近圆，但相邻航点距离也越小。如果到达容差过大，可能出现相邻目标的容差区域重叠，使进度判断失去意义。
YAML参数：增加了circle_radius: 1.0和circle_points: 12
